# 장소 검증 사용 방법

1. 관리자 화면의 장소 ID 입력 후 `기준 이미지 등록`을 펼칩니다.
2. 장소의 기준 사진을 선택하고 `현재 장소에 저장`을 누릅니다.
3. 같은 장소 ID로 QR을 발급하고 학생 앱에서 촬영·인증합니다.
4. 인증 현황의 행을 클릭하고 `장소 상세`를 누릅니다. 매칭 수·Inlier 수와 비율, 실제 기준과 촬영 이미지 연결 그림이 표시됩니다.

SIFT 최대 3000개 특징점 → L2 거리 최근접 매칭 → Ratio test 0.75 → 중복 대상점 제거 → RANSAC Homography(축소 이미지 기준 3px) 순서입니다. 검증 전 이미지는 긴 변 최대 1600px로 맞춥니다. 유효 매칭 중 Inlier 비율을 사용합니다. 충분한 대응점이나 안정적인 변환이 없으면 불일치로 단정하지 않고 판정 불가로 처리합니다.

기본값 **Inlier 20개, 비율 40%**는 구현 확인용 임시 시연값입니다. 논문에서 검증된 기준이나 정확도 보장이 아닙니다. 정상 장소·다른 장소·유사 장소의 실제 사진으로 조정해야 합니다. 두 기준을 모두 충족해야 일치입니다. 기준 사진을 다시 등록하면 설정도 갱신되며 기존 인증 결과에 사용된 사진과 기준은 보존합니다.

연결 그림은 초록 Inlier, 빨강 Outlier이며 보기 좋게 거리순 최대 100개만 표시합니다. 계산에는 전체 유효 매칭을 사용합니다. 수치를 현장 존재 확률로 해석하지 않습니다. Inlier가 많아도 반복 무늬·같은 포스터·전달받은 사진을 동일 장소로 오인할 수 있습니다. 특히 QR 자체가 공통 특징으로 작용할 수 있으므로 QR이 화면 대부분을 차지하는 사진은 피하고 주변 환경 중심의 기준 사진으로 검증하세요. QR 영역 자동 마스킹은 현재 포함하지 않습니다.

API: POST /api/places (PlaceRegistration), GET /api/places, GET /api/references/{reference_id}, GET /api/attempts/{attempt_id}/matches. 관리자 PC에서만 접근 가능하며 POST에는 X-Attendance-Admin: 1 헤더가 필요합니다.

사진은 server/data/places, 매칭 그림은 server/data/matches, 입력 사진은 server/data/images에 저장하며 Git에서 제외됩니다. 서버 data 폴더에 실제 사진을 넣어도 커밋되지 않습니다.
